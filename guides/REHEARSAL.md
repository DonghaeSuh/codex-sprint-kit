# 별도 폴더에서 60분 리허설

첫 연습은 작업 60분 + AI 없이 설명 15분입니다. 실제 대회 문제나 답안을 사용하지 않습니다.
모의과제와 실무자 비밀 설정은 이 공개 저장소에 포함하지 않습니다.
개인 준비 폴더에 생성된 START.md가 있다면 **그 파일의 두 터미널 명령만** 따르면 됩니다.
이 문서는 준비 방식과 진행 기준을 설명합니다.

## 폴더와 역할
- candidate: 모의과제 README·입력 자료·키트·실제 구현과 .sprint 기록.
- stakeholder: 역할극 지침과 비밀 설정. 별도 읽기 전용 Codex 세션에서 사용.
- review: 종료 후 본인이 작성하는 설명과 회고.
- START.md: 사람용 시작 안내. 구현 세션에는 전달하지 않음.

두 폴더·프롬프트는 답안 노출을 줄이는 운영 구분이며 OS 수준의 읽기 차단은 아닙니다.
구현 세션은 candidate 밖의 비밀 설정·다른 답안·과거 리허설 해설을 읽지 않습니다.
실무자 세션은 설정 전체를 공개하지 않고 질문받은 내용만 답합니다.
같은 폴더에 두 하네스의 bootstrap을 함께 실행하지 않습니다.

## 시작
1. 새 연습 폴더를 준비합니다. 원본 모의과제는 보존하고 workspace만 candidate에 복사합니다.
2. 공개 키트 파일만 candidate/codex-sprint-kit에 둡니다. 인증·사용자 설정·.git 이력은 필요 없습니다.
3. 실제 문제 README는 candidate 루트에 보존합니다. 키트 README로 바꾸지 않습니다.
4. 별도 터미널에서 실무자 역할극을 준비합니다. 비밀 설정은 미리 직접 읽지 않습니다.
5. 준비됐을 때 candidate에서 아래처럼 60분을 시작합니다.

```bash
python3 codex-sprint-kit/scripts/init_workspace.py --root .
python3 codex-sprint-kit/scripts/timer.py start --root . --minutes 60
codex '60분 로컬 모의과제다. README.md와 codex-sprint-kit/SESSION.md를 읽고 진행해줘. 실무자 답변은 내가 전달한다. 현재 작업 폴더 밖 비밀 설정·다른 연습·과거 해설은 읽지 말고, 실제 요구 파일 경로를 지켜줘. 기존 타이머를 유지해줘.'
```

시작 문장은 그대로 입력할 수 있습니다. 이 블록은 candidate 폴더에 입력 파일과 키트가 준비된 뒤 실행합니다.
실제 시험에서는 개인 연습 폴더나 비밀 설정을 반입하지 않습니다.

## 60분 일정
| 시간 | 사용자 | Codex |
|---|---|---|
| 0–5 | 과제·제출 조건 확인 | 환경·데이터 파악 |
| 5–12 | 실무자 질문·답변 전달 | 질문/답변→요구사항→검사 연결 |
| 12–27 | 중요 선택 확인 | 첫 핵심 흐름 구현 |
| 27–42 | 실무자 중간 확인 | 필수 기능·실패 사례 개선 |
| 42–47 | 직접 화면 조작 | 통합 검사 |
| 47–55 | 새 기능 중단 | 결함 수정·검증·최종 문서 |
| 55–60 | 설명·결과 확인 | DEFENSE·최종 상태 정리 |

작업 중 수동 UI를 확인할 때 로컬에서는 실제 서버 포트로 브라우저를 엽니다.
본시험에서는 제공된 내장 Browser와 해당 규정을 따릅니다. 자동 브라우저 조작은 사용하지 않습니다.
27분까지 핵심 흐름이 없으면 선택 기능을 줄이고, 47분부터 기능을 동결합니다.
설정에 없는 업무 규칙은 '미정'으로 남깁니다. 실무자 답변 대기 중 독립 작업은 진행합니다.

## 종료 후 15분
두 AI 작업을 멈추고 세 질문에 각각 5분 동안 직접 답합니다.
1. 핵심 동작과 실제 확인 방법은?
2. 실무자 답변이 요구사항·구현을 어떻게 바꿨는가?
3. 남은 약점·영향·다음 검증은?

답변을 마친 뒤에만 비밀 설정과 비교합니다. 공식 채점 비중이나 점수를 추측하지 않습니다.
요구 파악·구현·검증·설명 중 가장 큰 병목 하나를 다음 연습의 개선 대상으로 정합니다.
실패했어도 시간을 늘려 성공처럼 만들지 않습니다. 다음 시도는 새 폴더에서 시작합니다.

## 확인해야 할 실제 결과
- 원래 과제 README와 입력 파일은 보존됐는가?
- 필수 제출 문서가 정확한 경로에 존재하는가?
- 질문으로 얻은 답변과 구현·검사 사이의 연결이 남았는가?
- 실행한 검사와 수동 관측, 미검증 내용이 구분되는가?
- 사람이 구조·결정·한계를 설명할 수 있는가?
- 비밀 설정을 직접 읽지 않고 진행했는가?

키트 테스트 통과는 모의과제 통과를 의미하지 않습니다. 연습 결과·원본 비밀 설정은 로컬에만 둡니다.
